# Способы защиты данных в «Медикаменте»

Я подбирал меры по тому, для чего сотрудник использует данные. Врачу нужен результат анализа именно его пациента. Кассир сверяет оплату по реквизитам операции. Для отчета о прибыли и убытках (P&L) аналитику достаточно доходов и расходов за период. Номера P01–P08 совпадают с обозначениями на схемах и в [списке проблем безопасности](02-security-problems.md).

## Предлагаемые меры по процессам

| Данные и процесс | Способ защиты | Как применить в клинике |
| --- | --- | --- |
| ФИО, дата рождения, телефон и почта пациента · P01, P02 | Шифрование при хранении, маскирование контактов при просмотре | Ресепшен сверяет ФИО и дату рождения при регистрации. В списке записей показывать последние четыре цифры телефона. Полный номер открывать сотруднику, который связывается с конкретным пациентом. |
| Договор пациента · P01 | Шифрование электронной версии, маскирование реквизитов в выдаваемых копиях | Если клиника хранит электронный экземпляр, выделить для него закрытую папку договоров. Для сверки номера и суммы выдавать выписку с этими двумя полями. Если получателю нужен PDF с закрытыми реквизитами, проверить, что их удалили и из текстового слоя. |
| Адрес, место работы или учебы в расширенной анкете · P01, P03 | Минимизация сбора, шифрование заполненной анкеты | Для каждого поля определить, кто и для чего использует ответ. В форму записи на прием включать только данные для записи и связи. Медицинскую часть анкеты открывать персоналу, участвующему в оказании помощи. |
| Запись к специалисту и журнал врача · P02 | Разграничение прав на расписание | Дать врачу доступ к журналу его приемов. Ресепшену для записи нужны пациент, специалист, время и контакт для напоминания. Для статистики загрузки врача выводить число записей за период. |
| ФИО и дата рождения в имени папки пациента, ФИО врача в имени журнала · P01–P03 | Псевдонимизация имен, ограничение просмотра каталогов | Присвоить папке внутренний номер пациента. Соответствие номера, ФИО и даты рождения хранить в отдельном закрытом реестре. По известному номеру доступ все равно проверяется. Для файла расписания использовать код врача. Сотрудник ресепшена выбирает врача по рабочему справочнику. |
| Медкарта, заключения, сведения о хронических заболеваниях, сканы · P03 | Шифрование оригиналов и копий, доступ по связи с пациентом | Лечащий или назначенный на замену врач получает полный документ. Ресепшену для записи достаточно административных данных. Просмотр и изменение карты фиксировать с указанием сотрудника, документа и времени. |
| Дневной реестр анализов, направление и результат · P04 | Псевдонимизация, шифрование при хранении и передаче | Для предлагаемого обмена использовать номер направления. С лабораторией согласовать данные, необходимые для идентификации пациента и пробы. Результат привязывать к исходному направлению. Таблицу соответствий держать в клинике с отдельными правами. Текущий канал обмена требует проверки. |
| Платеж, сумма, чек и связь с договором · P05 | Шифрование базы, сокращение состава сверочной выгрузки | Согласовать общий идентификатор операции для кассы и 1С. В таблице сверки оставить этот идентификатор, сумму и статус. Для связи ККМ с 1С проверить, какой защищенный канал поддерживают касса и ее драйвер. |
| Кадровые сведения, начисления сотруднику и налоговые документы · P06 | Шифрование файловой базы и выгрузок, разделение прав в 1С | Индивидуальные начисления открывать бухгалтеру, который рассчитывает зарплату. Кассовой роли оставить операции оплаты. Проверить права и на файл базы, из которого можно получить обе группы сведений. |
| ТМЦ, закупки и возможные контакты представителей поставщиков · P07 | Минимизация обмена, разграничение доступа к контактам | Для каждого направления обмена между базами 1С согласовать состав полей. Если бухгалтерии для проводки нужны номер документа, позиция и сумма, передавать эти реквизиты. Доступ к контактам представителя оставить сотрудникам, которые ведут закупку. |
| Рабочие выборки Excel и блокноты Jupyter · P08 | Удаление лишних столбцов до загрузки, ограничение доступа к рабочим копиям | Для P&L передавать аналитику период, статьи, доходы и расходы. Для ABC по услугам достаточно кода услуги и значения выбранного показателя. Перед выдачей блокнота проверить также сохраненный вывод ячеек. |
| Итоговые аналитические отчеты · P08 | Обезличивание аналитической выгрузки через агрегирование и проверку результата | Подготовить сводку по периодам и группам услуг. Если по одному визиту в филиале можно узнать пациента, укрупнить период или объединить группы. При выдаче сравнить сводку с соседними срезами, из которых можно вычислить скрытое значение. |
| Доменные учетные записи и членство в группах · D11, все процессы | Именные учетные записи, ограничение и отзыв прав | Для администрирования выделить отдельную учетную запись. При смене должности пересмотреть группы, при увольнении отключить учетную запись. Изменения состава групп доступа к медкартам передавать ответственному за ИБ. |

## Как применять эти меры

На общем диске предлагаю выдать права группам Active Directory и проверить их под обычными учетными записями врача, кассира и сотрудника ресепшена. Для медкарт и зарплатных документов на файловом сервере нужны аудит файловой системы Windows и правила аудита на самих папках. Так можно различить чтение и запись файла. Чтобы установить, какую запись исправили внутри книги Excel, понадобится еще и история версий. [Аудит файловой системы Windows][audit]

Тома с документами и файловыми базами 1С предлагаю зашифровать. При работе с общим диском по сети — включить шифрование SMB и проверить совместимость рабочих мест. Резервные копии тоже требуют шифрования. Ключ восстановления нужно держать отдельно и проверить, что с ним можно открыть копию медкарты и восстановить базу на другом сервере. [Шифрование SMB][smb] · [Рекомендации OWASP по защите хранимых данных][storage]

Маскирование — один из способов обфускации. Для просмотра расписания хватит последних четырех цифр телефона. При выгрузке в Excel нужно сформировать отдельную книгу, куда попадут только эти цифры. Если просто скрыть столбец в исходной книге, получатель сможет снова его открыть. [Справка Excel о скрытых столбцах][workbook]

Лаборатории предлагаю передавать номер направления и согласованные с ней поля. Пока в клинике можно связать номер с пациентом, результат требует такой же защиты, как именной документ. Для аналитической сводки критерий другой. Перед выдачей владелец данных проверяет, можно ли установить человека по сочетанию филиала, даты и услуги с учетом других доступных получателю отчетов. [Рекомендации NIST по оценке риска повторной идентификации][deid]

При запросе пациента на прекращение обработки ответственный ищет его записи и выгрузки по реестру. Для каждой копии проверяет цель, основание и обязательный срок хранения. Если основание для дальнейшей обработки отпало, прекращает выдачу и организует удаление. Если закон требует сохранить документ, ограничивает его использование этой целью. При восстановлении из резервной копии нужно повторно применить решения об удалении до возврата данных в работу. [Аудит и основания хранения](02-security-problems.md)
