# Реестр программных и аппаратных средств

В реестр я включил средства для действующей сети клиники и новой платформы. Шлюзы, службу управления ключами и резервное оборудование предстоит выбрать для конкретной площадки. [Классификация данных и выбор мер](README.md)

| Средство | Тип | Место применения | Назначение |
| --- | --- | --- | --- |
| Microsoft BitLocker | Программное | Windows Server и управляемые рабочие места | Шифрует тома с папками пациентов, базами 1С, каталогом Active Directory и локальными выгрузками. |
| Дискретный модуль TPM 2.0 | Аппаратное | Сервер или рабочая станция с BitLocker, при наличии совместимого модуля | Привязка разблокировки системного тома к доверенному состоянию загрузки. Для восстановления при замене оборудования нужен отдельный ключ. |
| Active Directory и файловая служба Windows Server | Программное | Рабочие места и сервер в клинике | Группы и разрешения NTFS ограничивают доступ к файлам. Файловая служба шифрует сеансы SMB 3. Права внутри базы задаются ролями 1С. [Шифрование SMB][smb] |
| VPN-шлюзы с поддержкой IPsec | Программно-аппаратное | Сеть филиала и сеть центра | Защищенный туннель между шлюзами для межофисного обмена. Защиту локального участка у кассы определяют по возможностям оборудования. |
| HTTPS-прокси, библиотеки TLS приложения Java и драйвер pgJDBC | Программное | Вход на платформу, внутренние API, лабораторный и платежный обмен, PostgreSQL | Прокси и клиенты проверяют сертификаты при установлении соединений. Для API лаборатории прокси проверяет сертификат партнера, приложение — принадлежность направления. [Проверка сервера в pgJDBC][jdbc] |
| cryptsetup и dm-crypt | Программное | При размещении PostgreSQL, ClickHouse и NiFi на Linux | Шифрование томов в формате LUKS2. На них размещаются также журналы транзакций, очереди и временные файлы. |
| Объектное хранилище с серверным шифрованием, служба управления ключами (KMS) и хранилище секретов | Программное | Хранилища меддокументов и аналитики, сервисы платформы | KMS управляет разными ключами для меддокументов и озера. Сервисы получают права на свой ключ. В хранилище секретов размещаются токены и данные для подключения. Интеграцию с KMS нужно проверить до загрузки данных. |
| Штатные средства копирования 1С и PostgreSQL, restic | Программное | Базы, документы и отдельный резервный репозиторий | Штатные средства готовят согласованную копию 1С или PostgreSQL. restic шифрует копию перед отправкой в репозиторий по SFTP и проверяет целостность сохраненных данных. [Проверка репозитория][restic] |
| Отдельное устройство хранения и отключаемый резервный носитель | Аппаратное | Вне офисного сервера, автономный экземпляр — в другом защищенном помещении | Сохраняют восстанавливаемый экземпляр при потере офисного сервера. Отключаемая копия недоступна из рабочей сети. |
| Диспетчер ресурсов файлового сервера (FSRM), Apache NiFi и тесты правил доступа | Программное | Общие папки NTFS, загрузка в озеро, конвейер выпуска приложения | FSRM ставит метки файлам. NiFi проверяет поля и метки выгрузки, тесты на синтетических записях проверяют права до выпуска. |
| Служба аудита, VictoriaMetrics, vmalert и Alertmanager | Программное | Клиническое приложение, KMS и мониторинг | Аудит хранит решения о доступе. VictoriaMetrics собирает счетчики и показатели состояния защиты, vmalert проверяет правила, Alertmanager направляет оповещение дежурному. |

За настройку инфраструктуры отвечает администратор, за допустимый состав выдачи — владелец данных. Проверки шифрования, доступа и восстановления описаны в [разделе 3 основного документа](README.md#3-автоматизированный-контроль).

[smb]: https://learn.microsoft.com/en-us/windows-server/storage/file-server/smb-security
[jdbc]: https://jdbc.postgresql.org/documentation/ssl/
[restic]: https://restic.readthedocs.io/en/stable/045_working_with_repos.html
