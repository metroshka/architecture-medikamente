# Критерии готовности проектной работы

## Task1. Анализ безопасности системы

- [x] Определены процессы, участники, хранилища и конфиденциальные данные.
- [x] Для каждого из восьми процессов есть отдельная DFD текущего состояния.
- [x] На DFD показаны направления передачи, состав данных и операции над ними.
- [x] Участники, системы и хранилища сверены с описанием клиники и исходной схемой.
- [x] На схемах отмечены предполагаемые маршруты и детали, требующие уточнения.
- [x] Существующие меры сопоставлены с требованиями к персональным данным и врачебной тайне.
- [x] Риски по процессам собраны в [отдельном документе](Task1/02-security-problems.md).
- [x] Для соответствующих видов данных выбраны шифрование, маскирование, псевдонимизация и обезличивание.
- [x] Описаны правила тегирования, инструменты и проверки при выдаче данных.
- [x] Для рассматриваемых потоков предложены инструменты и меры защиты.
- [x] Для каждой DFD есть версия с мерами по этапам. Обе версии доступны из [реестра](Task1/01-data-inventory.md).

## Task2. Проектирование решения

- [x] Контекстные диаграммы C4 показывают запись в MVP и работу платформы через год.
- [x] Обозначено, какие операции выполняет ресепшен и какие переходят к платформе.
- [x] Описано, где платформа проверяет права, отбирает поля и фиксирует обращения к данным.
- [x] На схеме аналитики показан путь от закрытой загрузки до выдачи витрины.
- [x] Подписаны роли, внешние системы и данные, которыми они обмениваются.
- [x] Внутренние механизмы защиты и аналитики раскрыты на диаграмме контейнеров.
- [x] Правила доступа сопоставлены с категориями данных и процессами из Task1.

- [x] Для выделенных классов обоснована необходимость защиты.
- [x] Отдельно рассмотрена защита при хранении и во время передачи.
- [x] Предложены базовые инструменты защиты.

## Уточнения к формулировкам задания

- В разделе сдачи упомянуты две директории, при этом описаны четыре задания. Структура проекта включает Task1–Task4.
- В Task2 указано целевое состояние, а в итоговом перечне — MVP. В решении необходимо явно отразить оба этапа.
- Количество DFD определяется выделенными процессами; фиксированное число диаграмм в задании не установлено.
- Микросервисная архитектура приведена как пример. Архитектурный стиль выбирается и обосновывается в ходе проектирования.
- Apache NiFi рассмотрен в учебных материалах как инструмент управления потоками; обязательное развертывание NiFi в задании не установлено.
