# Критерии готовности проектной работы

## Task1. Анализ безопасности системы

- [ ] Определены процессы, участники, хранилища и конфиденциальные данные.
- [ ] Для каждого выделенного процесса подготовлена отдельная DFD текущего состояния.
- [ ] На DFD показаны перемещение данных, состав потоков и операции над данными.
- [ ] Проверена полнота относительно описания компании и исходной архитектуры.
- [ ] Подтверждённые сведения отделены от допущений и неуточнённых деталей.
- [ ] Проведён аудит мер защиты с учётом требований и архитектурных практик.
- [ ] Список проблем сохранён отдельным документом.
- [ ] Для данных определены применимые способы защиты: шифрование, обфускация, обезличивание.
- [ ] Описан механизм тегирования данных и выбранные инструменты.
- [ ] Предложены инструменты и меры защиты для рассматриваемых потоков.
- [ ] Подготовлены отдельные версии DFD с мерами защиты на соответствующих этапах; As-Is сохранены.

## Task2. Проектирование решения

- [ ] Подготовлена контекстная диаграмма C4.
- [ ] Явно обозначены границы MVP и развитие до целевого состояния.
- [ ] Предложены архитектурные блоки, обеспечивающие Privacy by Design.
- [ ] Предусмотрен аналитический слой с защитой конфиденциальных данных.
- [ ] Показаны пользователи, внешние системы и взаимодействия.
- [ ] При необходимости внутренние механизмы раскрыты дополнительной диаграммой контейнеров.
- [ ] Решения согласованы с потоками и проблемами из Task1.

## Task3. Защита данных при хранении и передаче

- [ ] Данные классифицированы по состоянию, чувствительности и профилю риска.
- [ ] Для выделенных классов обоснована необходимость защиты.
- [ ] Отдельно рассмотрена защита при хранении и во время передачи.
- [ ] Предложены базовые инструменты защиты.
- [ ] Предложены средства автоматизированного контроля.
- [ ] Подготовлен реестр программных и аппаратных средств защиты.
- [ ] Подготовлена итоговая таблица: данные, необходимость защиты, инструменты защиты.
- [ ] Предложения согласованы с Task1 и Task2.

## Task4. Оценка узких мест при миграции

- [ ] Определены цели миграции и затрагиваемые процессы и компоненты.
- [ ] Построена диаграмма Исикавы в формате draw.io.
- [ ] Выделены категории причин и возможные проблемы в каждой категории.
- [ ] Рассмотрены риски снижения производительности и нарушения работоспособности.
- [ ] Для выявленных проблем предложены меры устранения.
- [ ] Определена приоритетность мер.
- [ ] Подготовлен отчёт с выявленными проблемами и решениями.
- [ ] Диаграмма и отчёт помещены в Task4.

## Проверка перед сдачей

- [ ] Репозиторий называется `architecture-medikamente` и имеет публичный доступ.
- [ ] Все результаты находятся в каталогах Task1–Task4.
- [ ] README содержит ссылки на готовые результаты.
- [ ] Диаграммы открываются, подписи читаются, обозначения согласованы.
- [ ] Ссылки на файлы работают.
- [ ] Указанные в решении нормативные и технические требования сверены с первоисточниками.
- [ ] Все изменения решений закоммичены в `solution` и опубликованы на GitHub.
- [ ] Pull request из `solution` в `main` содержит все решения и остаётся открытым.
- [ ] На ревью передана ссылка на pull request.

## Уточнения к формулировкам задания

- В разделе сдачи упомянуты две директории, при этом описаны четыре задания. Структура проекта включает Task1–Task4.
- В Task2 указано целевое состояние, а в итоговом перечне — MVP. В решении необходимо явно отразить оба этапа.
- Количество DFD определяется выделенными процессами; фиксированное число диаграмм в задании не установлено.
- Микросервисная архитектура приведена как пример. Архитектурный стиль выбирается и обосновывается в ходе проектирования.
- Apache NiFi рассмотрен в учебных материалах как инструмент управления потоками; обязательное развёртывание NiFi в задании не установлено.
